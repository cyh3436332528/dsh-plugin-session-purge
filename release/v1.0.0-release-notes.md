### Release Notes（直接粘贴进 Release 正文）

```markdown
DSH 自带的「归档」只把会话从列表里隐藏，磁盘上的日志与投影缓存一个字节都不动。
**1.0.0 补上的就是缺失的那一步：真删。**

## 功能

- **两个入口**：设置页「会话管理」分区，以及对话头部的删除按钮。
- **永久删除 + 级联清理**：一次删除同时处理四类关联数据。

  | 关联数据 | 磁盘位置 | 处理方式 |
  |---|---|---|
  | 会话日志 | `~/.dsh/sessions/<工作区文件夹>/<会话ID>/` | 递归删除整个目录 |
  | 投影缓存 | `~/.dsh/storages/session_projcache/sessions/<会话ID>.json` | 删除文件 |
  | 工作区记账 | `~/.dsh/storages/workspace.json` | 解除归属（域表 + 全局归档表） |
  | 子会话（子代理） | 同工作区文件夹下的子代理会话 | 可选一并删除 |

- **子会话判定保守**：与父会话同 workspace 文件夹、且不在任何 workspace 的 `sessionIds` 里。
  该规则保证**不会误删别的正常会话**。
- **列表面板**：按工作区分组，每行显示标题、会话 ID、体积、目录最后修改时间；
  带 `打开中` / `已归档` / `子会话 N` / `无工作区` 状态标记；支持筛选、多选批量删除、
  以及独立的「删除全部已归档会话」卡片。
- **误触防护**：确认块出现在触发按钮**下方的独立区块**，取消是白色主按钮且佔住指针原来停留的位置，
  删除是整页唯一的红色按钮，两者之间隔着一整段空白。
- **渲染隔离**：面板整体包在 React error boundary 内，插件渲染失败不会影响设置面板的其他分区。
- **跟随设计系统**：普通按钮用官方 `@deepseek-ai/dsh-client-ui-primitives`，
  配色走 `--dsw-alias-*` CSS 变量，浅色 / 深色主题自动适配。
- **无配置项、无运行时依赖、无构建步骤。**

## ⚠️ 删除不可恢复

- 删除**不进入回收站**，不提供撤销，不做二次备份。
- 被删会话的对话记录、工具调用记录、上下文投影缓存与（勾选时的）子代理记录会一并消失。
- **删之前请自行备份** `~/.dsh/sessions/<工作区文件夹>/<会话ID>/` 整个目录。
- 只想保留归档、不想真删的话，请用 DSH 自带的归档功能，**不要用本插件**。

## 已知限制

- **处于「打开中」状态的会话，其列表项要等 DSH 重启后才会消失。**
  文件是实时删除的；插件刻意保留它的工作区归属，避免它在侧栏被踢进「未分组」。
  界面会明确提示这一点。
- **`plugin/package.json` 缺少 `dsh.compatibility` 字段。**
  本项目在 DSH Desktop `0.1.x` 系列上开发并实测，但尚未以字段形式固化兼容区间。
- **删除路径没有自动化测试覆盖。**
  `plugin/_smoke.mjs` 是只读冒烟脚本，只验证 `/list` 路由。
```

## 二、git tag 方案

### 标签格式

```
v<major>.<minor>.<patch>
```

即 **带 `v` 前缀**的 SemVer。理由：

- 与 DSH 生态既有插件（`dsh-better-sidebar` v0.22.1、`dshmarket` 1.66.1 等）的 Release 习惯一致，社区工具链普遍按 `v*` 匹配；
- 与 `package.json` 的 `version`（**不带** `v`，值为 `1.0.0`）区分开，一眼能看出谁是 npm 版本、谁是 git 标签；
- GitHub Release 的自动 tag 建议也默认 `v` 前缀。

### 本版本的标签

| 项 | 值 |
|---|---|
| tag 名 | `v1.0.0` |
| tag 类型 | **annotated**（轻量标签不带附注，不利于归档） |
| 指向 | `main` 上 `package.json` 版本为 `1.0.0` 的那个提交 |
| 标题 | `dsh-plugin-session-purge v1.0.0` |

### 创建命令

```bash
# 确认工作区干净、且版本号已对齐
git status
git log --oneline -1

# 创建带附注的标签
git tag -a v1.0.0 -m "dsh-plugin-session-purge v1.0.0

首个正式版本：设置页 + 对话头部两个入口，永久删除会话并级联清理
日志、投影缓存、工作区记账与子会话。

删除不可恢复。"

# 推送标签
git push origin v1.0.0
```

### 后续版本的递增规则

| 变更类型 | 递增位 | 示例 |
|---|---|---|
| 修 bug、改文档、改文案 | patch | `v1.0.0` → `v1.0.1` |
| 新增向后兼容的功能 | minor | `v1.0.0` → `v1.1.0` |
| 破坏性变更（接口、删除范围、配置语义） | major | `v1.0.0` → `v2.0.0` |

**特别约定**：任何**扩大删除范围**的改动，即便功能上向后兼容，也按 **major** 处理。
用户需要据此判断是否值得重新评估风险。

### pre-release 约定（如需）

发布预览版时使用 SemVer 的 prerelease 段，且**必须**在 GitHub Release 上勾选 *Set as a pre-release*：

```
v1.1.0-rc.1
v1.1.0-alpha.1
```

`dsh` CLI 的版本区间解析支持这种形式，社区插件也普遍采用（如 `0.1.5-alpha.1`）。

### 事实：不提交就不会出现在插件广场

已实测确认：市场索引 `https://awesome-dsh-plugin.com/plugins.json`（共 **4377** 个插件）
中**搜不到** `session-purge` —— **0 命中**。也就是说，**光有 GitHub 仓库，别人在插件广场里是找不到你的。**

### 提交方式：一个文件 + 一个 PR

1. Fork `awesome-dsh-plugin/awesome-dsh-plugin`
2. 新增 **一个文件**：`data/plugins/cyh3436332528__dsh-plugin-session-purge.yml`
   （内容即本仓库的 `release/awesome-dsh-plugin-entry.yml`，已按规范写好）
3. 提 PR。**不要手工编辑 README** —— 那两个 README 由 `data/plugins/*.yml` 自动生成

### 可选但推荐

若**不发布 npm**，建议把预构建 tarball 挂到 GitHub Release，并在条目里加 `tarball:` 字段指过去——
市场会优先展示 tarball 而不是源码构建命令。本插件是纯 JS、无构建步骤，源码安装即可用，**此步非必需**。

### 关于「和 DSH 官方挂钩」

**没有官方对接渠道。** 官方 `deepseek-ai/deepseek-harness` 仓库的
`docs/user/develop/basic/publish.md` 只讲了「怎么把插件打包成 bundle 并用 `dsh plugin add` 安装」，
**没有**任何「提交插件到官方市场」的流程——因为官方不运营插件市场。
社区生态完全建立在三件事上：

1. 仓库声明 `dsh.bundle`（**这是唯一的机器可读契约**）
2. 仓库打上 `dsh-plugin` topic（GitHub 层的发现机制）
3. 向 awesome-dsh-plugin 提 PR 收录（第三方目录）

`dshmarket`、`dsh-find-plugin` 这类插件市场客户端，正是靠读这些数据来展示插件的。
